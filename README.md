# Django-проект: Онлайн-каталог товаров и Блог оповещения <img width="137" height="41" alt="Skypro" src="https://github.com/user-attachments/assets/ac708293-d4d3-4222-980d-a89643052ae0" />

Веб-проект на базе фреймворка **Django**, реализующий динамическую структуру интернет-магазина-каталога с интегрированным новостным блогом, поддерживающим полный цикл CRUD-операций. Архитектура построена на базе классов (CBV), ORM-моделей, валидных HTML-форм, единой системы наследования шаблонов, менеджера окружения `mailers` и СУБД PostgreSQL.

## 🛠 Выполненные задачи (Критерии проверки)

### 1. Рефакторинг, оптимизация контроллеров на CBV и полный CRUD продуктов
* **Перевод на классы:** Все существовавшие FBV-контроллеры приложения `catalog` (включая главную страницу, детальный просмотр, страницу контактов с обработкой POST-форм и создание продуктов) полностью переписаны на высокоуровневые **Class-Based Views** (`ListView`, `DetailView`, `TemplateView`, `CreateView`, `UpdateView`, `DeleteView`).
* **Разделение логики каталога и администрирования:** Чтобы сохранить чистый дизайн главной страницы, весь CRUD-функционал управления вынесен в изолированную панель управления `ProductManageListView` (доступна по клику на вкладку «Редактировать» в сайдбаре).
* **Синхронизация моделей:** Страница категорий полностью переписана с ошибочной модели `Product` на правильную архитектурную модель `Category` для динамического вывода групп товаров компании.
* **Кастомная валидация форм:** В класс формы `ProductForm` интегрирована строгая проверка запрещенных слов (`FORBIDDEN_WORDS`), кастомная валидация отрицательной цены через `clean_price` и проверка загружаемых изображений (форматы JPEG/PNG, размер до 5 МБ).

### 2. Разработка изолированного приложения Блога
* **Архитектурный модуль:** Создано и зарегистрировано в `settings.py` новое Django-приложение `blog`.
* **ORM-модель данных:** Реализована модель `BlogEntry` с автоматическим полем даты создания (`DateTimeField(auto_now_add=True)`), флагом публикации, счетчиком просмотров и строковым методом `__str__`. Настроена мета-информация класса для корректного отображения в панели администратора на русском языке.
* **База данных:** Созданы и успешно применены новые файлы миграций для интеграции таблиц блога в PostgreSQL.

### 3. Реализация CRUD-функционала и умных счетчиков в блоге
* **Полный CRUD:** На базе CBV реализован полный цикл управления записями по префиксу `blogs/` через контекстные URL (заканчивающиеся на слэш `/` согласно ТЗ):
  * `BlogEntryListView` — Вывод списка опубликованных статей (настроена фильтрация `get_queryset`).
  * `BlogEntryDetailView` — Детальный просмотр статьи с динамическим инкрементом просмотров.
  * `BlogEntryCreateView` — Форма создания новой записи.
  * `BlogEntryUpdateView` — Редактирование статьи с динамическим редиректом (`get_success_url`) на страницу обновленной записи.
  * `BlogEntryDeleteView` — Удаление статьи с возвратом на список.
* **Счетчик просмотров:** Переопределен метод `get_object` в детальном контроллере блога: при каждом успешном открытии статьи счетчик `views_count` инкрементируется на 1 и сохраняется в БД.

### 4. Автоматическое почтовое уведомление (Доп. задание со звездочкой)
* Внедрена отправка электронных писем с использованием современного пакетного менеджера почты Django **`mailers`**.
* Добавлена логика автоматического триггера: когда счетчик просмотров статьи `views_count` достигает ровно **100 просмотров**, система автоматически формирует и генерирует поздравительное письмо на адрес администратора, указанный в скрытых переменных окружения.

### 5. Система аутентификации и кастомных пользователей (Задание 27)
* **Кастомная модель User:** Разработано новое приложение `users`. Стандартная авторизация Django полностью переведена на **Электронную почту (email)** вместо `username`. Добавлены новые поля согласно ТЗ: *Аватар*, *Номер телефона* и *Страна*.
* **Регистрация с приветственным письмом:** Создана форма регистрации со стилизацией полей и валидацией пароля. После успешной регистрации на почту пользователя автоматически отправляется приветственное письмо с указанием его логина.
* **Авторизация и Выход:** Настроена кастомная форма авторизации с короткими понятными сообщениями об ошибках на русском языке. Ссылки на выход из системы переведены на безопасный POST-метод.
* **Редактирование профиля (Доп. задание со звездочкой \*):** Создан контроллер на базе `UpdateView` и шаблона `profile.html`, позволяющий пользователю изменять свои персональные данные и загружать аватар.
* **Разграничение прав доступа в UI:** Подшаблон бокового меню `menu.html` адаптирован под проверку авторизации: гостям сайта закрыт визуальный доступ к страницам «Добавить товар» и «Редактировать», а внизу отображается динамический профиль залогиненного пользователя.

### 6. Безопасность и архитектура окружения
* Личные контактные данные администратора (`ADMIN_EMAIL`) вынесены в изолированный файл `.env` для предотвращения компрометации данных в публичных Git-репозиториях.
* Все URL-маршруты приложений вынесены в локальные файлы `urls.py` и подключены в главном конфигурационном узле `config/urls.py` через метод `include` с использованием пространств имен (`namespace`).
* Интерфейс всех страниц авторизации, регистрации и редактирования профиля приведен к общему UX-стилю, центрирован и зафиксирован ровно на **треть экрана** для удобства работы.

## 🚀 Инструкция по запуску проекта

### 1. Клонирование репозитория и переход в рабочую ветку
```bash
git clone <ссылка_на_твой_репозиторий>
cd 27_Django_DZ
```

### 2. Настройка файлов окружения
Создайте в корневой директории проекта файл **`.env`**. Обязательно настройте доступы к вашей базе данных PostgreSQL:
```env
SECRET_KEY=django-insecure-your-actual-secret-key
DEBUG=True

NAME=23_Django_DZ
USER=postgres
PASSWORD=ваш_пароль_от_postgres
HOST=localhost
PORT=5432

# Настройки почты
ADMIN_EMAIL=user@example.com
```

### 3. Установка зависимостей и активация окружения через Poetry
```bash
poetry install
poetry shell
```

### 4. Применение миграций (включая каталог, блог и пользователей)
Так как используется кастомная модель пользователей, миграции приложения `users` применятся в пустую БД первыми в очереди:
```bash
python manage.py makemigrations
python manage.py migrate
```

### 5. Создание суперпользователя и загрузка демо-товаров
```bash
python manage.py createsuperuser
python manage.py loaddata catalog/fixtures/27_catalog.json
python manage.py runserver
```
* Главная страница каталога товаров: [http://127.0.0](http://127.0.0)
* Главная страница списка статей блога: [http://127.0.0blogs/](http://127.0.0blogs/)
* Страница регистрации пользователей: [http://127.0.0users/register/](http://127.0.0users/register/)
* Административная панель Django: [http://127.0.0admin/](http://127.0.0admin/)
